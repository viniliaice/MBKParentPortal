# MBKConnect Android release remediation status

**Audit date:** 2026-11-04

**Status:** source/configuration remediation implemented; a signed production release and Play/device verification remain blocked in this workspace.

## 1. Initial diagnosis

- This is an **Expo SDK 54 / React Native 0.81.5 Continuous Native Generation (CNG)** project. There is no checked-in `android/` directory, Gradle wrapper, native manifest, or manually maintained `MainActivity`. Native changes must be made through app config/config plugins.
- Verified identity: app name `MBK Parent Portal`, Android ID `com.MBKConnect`, version name `1.0.0`. `app.json` contains a local `android.versionCode` seed of `1`; `eas.json` uses `appVersionSource: remote` and production `autoIncrement: true`, so the remote EAS value is intended to govern. The remote value/current Play code 8 could not be queried here.
- The production EAS profile already produces an App Bundle and does not auto-submit to Play. Signing is EAS-managed; no keystore was modified.
- In an isolated SDK 54 CNG generation, release minification and resource shrinking were **off by default** and the generated app used `proguard-android.txt`, the non-optimized Android default. This is consistent with the reported low obfuscation/optimization. The Android Gradle wrapper generated by SDK 54 is 8.14.3; AGP's resolved runtime version was not available without a Gradle/JDK build.
- Expo SDK 54's native source also contains several deprecated API references reported by Play. These are upstream framework/library call sites, not calls in application TypeScript.
- The scanner is not an application feature/dependency in `package.json`; the installed `expo-dev-launcher` brings `play-services-code-scanner:16.1.0` and `com.google.mlkit:barcode-scanning:17.3.0` for its development QR scanner. `expo-dev-menu` also brings Material Components 1.2.1. Both are development tooling and should not be in the Play build.

## 2. Changes implemented

- `app.json`: changed orientation from `portrait` to `default`; added `expo-build-properties` with release minification and resource shrinking enabled; added persistent local config plugins.
- `app.config.js` and `plugins/withProductionNativeExclusions.js`: retain the development client in development/preview, but in the `production` EAS profile exclude `expo-dev-client`, `expo-dev-launcher`, `expo-dev-menu`, and `expo-dev-menu-interface` from Android autolinking. The production plugin also removes only the development `exp+...` URL scheme, leaving the app's `mobile` scheme intact.
- `plugins/withOptimizedR8.js`: fail-fast CNG transform replaces the generated non-optimized `proguard-android.txt` default with `proguard-android-optimize.txt`. It refuses to silently continue if the generated template changes unexpectedly.
- `package.json` / `package-lock.json`: added Expo SDK 54-compatible `expo-build-properties` 1.0.10.
- `eas.json` was left unchanged. EAS artifact retention for the R8 mapping file is not configured; access to the mapping file from a future build must be confirmed through the existing build workflow.
- No application ID, Firebase/Supabase configuration, credentials, authentication, production data, or backend code was changed.

## 4. Android 15 edge-to-edge findings

Application code has no direct calls/configuration for `setStatusBarColor`, `getStatusBarColor`, `setNavigationBarColor`, `getNavigationBarColor`, status/navigation bar colors, or translucent bar props. The app uses `expo-status-bar` for icon/text style, `SafeAreaProvider`/safe-area insets, and `KeyboardProvider`. Generated SDK 54 Gradle configuration has edge-to-edge enabled and targets Android API 36.

The following upstream call sites **remain in the installed compatible SDK 54 source** and need a coordinated Expo/RN dependency upgrade or upstream-supported fix before claiming the Play warning is eliminated:

- React Native **0.81.5**: `ReactAndroid/.../modules/statusbar/StatusBarModule.kt` reads/writes `Window.statusBarColor`; `ReactAndroid/.../views/view/WindowUtil.kt` contains legacy status/navigation color setters and `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` / `...DEFAULT` branches. The app only requests status-bar style, but the deprecated source code is still in the framework.
- `react-native-screens` **4.16.0**: `ScreenWindowTraits.kt` reads/writes `window.navigationBarColor`; its bottom-sheet implementation depends on Material Components **1.12.0**.
- `react-native-keyboard-controller` **1.18.5**: `StatusBarManagerCompatModuleImpl.kt` retains a status-color fallback path; the library otherwise uses `WindowInsetsCompat` for edge-to-edge keyboard handling.
- `expo-dev-launcher` **6.0.21** has a `DevLauncherExpoActivityConfigurator` with legacy bar calls. The production autolinking exclusion removes this module from the intended Play build.
- `expo-dev-menu` **7.0.19** brings Material Components **1.2.1**. The production autolinking exclusion removes this dependency chain from the intended Play build.

No direct patch to `node_modules` or unsafe API suppression was made. The app-level safe-area and keyboard setup was audited, but no Android 13–16 visual/device tests were possible here. Do not mark the deprecated API warning resolved until the final AAB is scanned and remaining framework call sites are addressed by a compatible upgrade.

## 5. Orientation and large-screen findings

- `app.json` now opts into the Expo `default` orientation rather than portrait lock.
- A throwaway CNG generation of the production profile (using an empty placeholder Google Services file only in `/tmp`, not in this repository) produced `MainActivity` with `android:screenOrientation="unspecified"`, no `exp+...` development scheme, and Gradle autolinking configured to exclude the development modules.
- The autolinking CLI, run with the exact generated exclusion list, resolved **no `expo-dev-*` Android modules**. Since the scanner SDK arrives through the excluded dev launcher, it is expected not to contribute its scanner activity to the production merged manifest.
- The actual merged release manifest was **not** generated. The Google ML Kit activity's absence in the merged production manifest is therefore not claimed as verified; it must be checked after Gradle manifest merging.
- Existing app root layout constrains content to a readable 720-point column and uses responsive widths; login uses a scroll view and safe-area padding. This is a source audit, not proof of tablet/foldable functionality. No phones, tablets, foldables, split-screen windows, or landscape device were available for testing.

## 6. Memory audit

No Android Vitals/Play Console data or native profiling environment was available. Code review found:

- Long message and homework lists use `FlatList` virtualization.
- The only prominent app image is a bundled logo rendered at 100×100; no camera, barcode, PDF-preview, or large attachment feature is present in this repository.
- The quiz interval has unmount cleanup; the notification-response subscription is removed on unmount. No Supabase Realtime subscriptions or `useQuery` cache consumers were found.
- A few short UI timeouts (0.4–1 second) remain; no sustained leak was demonstrated from source review.

These observations do **not** establish safe RSS, bitmap, foreground/background, or long-session memory. No `adb`, Android Studio profiler, Java, Android SDK, device/emulator, heap dump, or Play Console memory breakdown was available. Android Vitals' aggregated real-user period cannot be cleared by local source review alone.
